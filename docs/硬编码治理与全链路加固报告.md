## 二、硬编码治理：系统级方案

### 2.1 配置层结构

```
backend/config/
├── pipeline.json      切片阈值 / CAD 几何判据 / 准入门禁 / 证据来源定义
├── domain.json        图层与箱号词典 / 断路器分类规则 / 电缆词法 / 核验判据 / 审核分级
├── pricing.json       铜价、工时、A/B 费率、品牌系数、兜底面价、钣金定额、候选打分权重
├── delivery.json      Excel 配色/表名/列宽、默认平替品牌、导出门禁、估算系数
├── replacement.json   国产化平替 品牌→系列 对照表
├── vision.json        视觉模型温度/超时/并发/重试/JSON 修复次数
└── model_pricing.json 模型费率卡（按生效日期分峰谷）
```

`extractor/config.py` 是唯一读取入口：

- **出厂默认随仓库发布**，代码读不到配置也不会崩（缺失键回落默认）；
- **`EXTRACTOR_CONFIG_OVERRIDE_DIR`** 指向目录放同名 JSON 即深度合并，现场只写要改的键；
- **JSON 内的 `_env` 段**声明「环境变量 → 配置路径」，值按默认值类型强制转换（`"12"` 不会变成字符串）；
- **`config_health()`** 自检当前生效的配置目录与已生效的环境变量，避免"以为改了其实没生效"。

### 2.2 已接入配置的模块（16 个）

`render.py`、`cad.py`、`cad_extractor.py`、`assemble.py`、`checker.py`、`catalog.py`、
`catalog_reconciler.py`、`normalizer.py`、`pricing.py`、`excel.py`、`vision.py`、`schema.py`、
`corroborate.py`、`app.py`、`frontend/app.js`、`frontend/index.html`

### 2.3 刻意留在代码里的常量

以下**没有**外置，因为它们是物理/协议常量而不是业务口径，外置只会增加出错面：

- 单位换算：`/ 1000.0`、`* 25.4`、`/ 72`；
- DXF 实体类型标识（`"LWPOLYLINE"`、`"INSERT"` 等）—— CAD 文件格式规范；
- 电气标准记法（`1P`/`2P`/`3P`/`4P`）；
- 除零保护 `1e-6`、百分比换算 `* 100.0`。

## 三、四个环节的保证方式

### 3.1 切片：如何保证所有图纸都切准

1. **网格由尺寸推导，不再写死。** 块数 = `页面实际尺寸 ÷ 目标块长边`，A4 到加长图共用同一套判据；
   密集系统图（矢量图元数超阈值）自动把目标长边从 300mm 收紧到 220mm，用更多块换更高有效分辨率。
2. **覆盖自检是硬门禁。** 切完立刻算 x/y 方向的区间并集覆盖率，铺不满整页直接抛错，
   **不允许带着漏区继续烧模型额度**。实测 8 种幅面（A4/A3/A2/A1/A0/1600×400/300×1200/2500×300）全部铺满。
3. **等效分辨率可算可查。** 每块按目标像素渲染，报告里给出 `effective_mm_per_px`，能量化"小字有多大"。
4. **切片计划入任务摘要**，导出前在界面上显示"几页切了几块、覆盖多少"。

### 3.2 解析：如何保证识别结果准确

1. **格式层**：Pydantic 强校验；JSON 结构/字段错误自动修复重试（次数可配）；
   截断是确定性失败，直接中止而不是让残缺数据流入 Excel。
2. **独立验证层（本次新增的关键能力）**：`corroborate.py` 把模型给出的纯事实字段
   （箱号、安装位置、防护等级、回路编号、断路器、电缆）拿去**图纸自带的原生文字**里核对：
   - 命中 → 证据来源升级为 `cad_native` / `pdf_text`，可判 `CONFIRMED`；
   - 未命中 → 保持 `PARSED_OK` 并汇总成一条 WARNING 待核对（**未命中不等于错误**）；
   - 没有原生文字 → 明确报告"交叉验证不可用"，不假装通过。
3. **不能让模型给自己作证**：`Evidence.origin` 区分来源，纯事实字段挂 `model_vision` 证据时
   最高只能到 `PARSED_OK`；`checker` 的 `EVIDENCE_STATUS_MISMATCH` 专拦"标称已确认却无物理来源"的真矛盾。

### 3.3 整合：如何保证按规则输出

元器件类别顺序、断路器分类规则、箱号词表、电缆词法、单位白名单、相序合法写法、
三相偏载阈值、价格候选打分权重——全部在 `domain.json` / `pricing.json` 里，改规则不改代码。

### 3.4 交付：Excel 怎么交付

1. **样式与结构配置化**：配色、表名、列宽、默认平替品牌都来自 `delivery.json`。
2. **导出不被遮挡（产品口径）**：**任何时候都能直接导出**。未确认的存疑项写进 Excel
   的待核对区并逐条列出，但不拦下载——导出是交付动作，不该被流程条条框框挡住。
   门禁机制保留但默认关闭（`delivery.json` 的 `export_gate.block_unresolved_default`），
   需要"存疑未清零不许导出"的项目可以自己打开。
3. **导面前自检面板**新增两行：**切片覆盖自检**与**关键字段独立交叉验证命中率**，
   让"切准了没""解析准了没"在交付前可见。
4. **金额诚实性**：价格库与标准面价库都未命中时不再用公式凑数，返回 0 并标注"待人工询价"
   （如项目明确接受估算，需在 `pricing.json` 打开开关，且金额自带"非供应商报价"标签）。

## 四、本次修复的真实缺陷

| # | 缺陷 | 风险 | 处理 |
|---|---|---|---|
| 1 | 循环证据链：程序把模型输出的值复制成 `TEXT` 证据，检查器按类型放行 | 防编造门禁形同虚设 | 引入来源标记 + 独立交叉验证 |
| 2 | CAD 原生提取器给每条进线硬填 `phase="L1/L2/L3/N/PE"` | 把假定当观测事实 | 优先取图上标注，未标注留空；如需假定走配置并自动注明 |
| 3 | 平替分析对未标额定电流的 ATSE/接触器执行 `int(None)` | 直接抛异常打断整条平替链 | 改为"电流待核"文案 |
| 4 | 价格库未命中时用公式推金额进入报价单 | 编造价格 | 失败关闭 + 配置开关 |
| 5 | 材料/板厚未收录时套用固定单价 146.90 元/㎡ | 编造价格 | 失败关闭 + 明确备注 |
| 6 | 导出门禁会拦住下载 | 拿不到文件，交付被流程卡住 | 改为**默认直接导出**，存疑项随 Excel 待核对区交出；门禁降级为可选配置 |
| 7 | 切片无覆盖校验 | 可能静默漏区 | 覆盖自检硬门禁 |
| 8 | 工程量写法被当作箱号（`380/220V`、`DC36V`、`50Hz`、`4X6A`） | 箱体误报 | 可配置的噪声正则，实测已排除 |
| 9 | 前端写死平替品牌下拉 | 改品牌要改前端 | 由 `/api/settings` 下发 |

## 六、还没有解决的差距（必须让决策者知道）

**这些不是"改改配置"就能解决的，直接决定能不能商用。**

1. **CAD 原生提取的箱体误报未根治。**
   照明图上抽出 172 个"箱体候选"，其中相当一部分（`380/220V`、`DC36V` 一类）已通过新增的
   工程量噪声正则排除，但仍有大量真实编号之外的候选。**根因是词法判据替代不了业务判断**：
   图纸上同名的行业术语（如消防回路编号 `FP-102`）在词法上和箱号无法区分。
   需要的是"先按图层/图框/目录清单锁定箱号集合，再逐条归属"，属于算法重构，本次未做。
   在此之前，**CAD 原生路径的输出必须逐条人工核对**，不能直接进报价。

2. **`01-制丝工房-动力配电0923.dwg`（23.8MB）读不进。**
   根因已定位：LibreDWG 转出的文本 DXF 里，代理/ACIS 实体带 `310` 组码的原始二进制字节，
   ezdxf 直接抛 `Invalid binary data`；改 `--as r2013` 无效；改二进制输出能过结构校验但撞到乱码图层名；
   `ezdxf.recover` 不支持二进制 DXF。
   **这不是切片参数问题，是转换器输出格式问题**，需要换转换器（ODA File Converter）或转换后剥离 ACIS 实体。
   → 影响 5 份 DWG 中的 1 份。

3. **没有"准确率"的真值集。**
   本次建立了可复跑的基准工具，但**只有人工清单可以作为召回率的分母**。
   目前桌面上的《四川中烟_利驰扒量_仅图纸有的元件.xlsx》口径与提取结果未必一一对应，
   要得到可信召回率，需要先约定标注口径（哪些元件进清单、多台箱体怎么折算）。
   **在补上真值集之前，任何"识别准确率 X%"的说法都不成立。**

4. **图片型 PDF 没有独立验证来源。**
   国内出图普遍文字转曲（项目里 2SAL2/2SAL3 实测 0 个词），这类图纸的交叉验证直接不可用。
   剩下的办法只有：接独立 OCR 做第二来源，或走人工抽查。**这属于能力缺口，不是配置问题。**

5. **价格库来源与有效期未逐条核验。**
   51061 行 `price_library.csv` 的出处、折扣有效性、含税口径没有数据行级证据。
   本次只保证"未命中就不编造"，**命中项的准确性仍依赖这份库的可信度**。

6. **任务表仍在进程内存里，必须单 worker。**
   多 worker 会拿到 404，重启会丢进行中的任务状态（产物文件还在）。属已知架构限制。

## 调整后的页面结构

```
项目列表  ──「新建项目」→（直接进入该项目）──┐
   │        └─「进入项目」→                 │
   │                                        ↓

                                 ├── 统计条：图纸数 · 已提取 · 箱体 · 回路 · 元器件 · 待核对 · AI 费用
                                 ├── 图纸清单：逐张「进入工作台」/「重新解析」/「移到其他项目」
                                 └── 「上传图纸到此项目」→ 上传页（顶部写清这批图进哪个项目）
                                        ↓ 提取完成
                                      工作台（面包屑「项目 › 图纸」，可一键点回项目）
```

导航从「项目 / 上传 / 工作台 / 历史记录 / 设置」收成「项目 / 工作台 / 历史记录 / 设置」——
上传不再是并列的一级入口，而是项目里的动作。历史记录页的每一行也能点回所属项目。

## 上传即建项目：归属怎么定

按可信度顺序取，任一命中即用，**绝不编造工程名称**：

| 优先级 | 来源 | 项目名来源标记 | 说明 |
|---|---|---|---|
| 1 | 上传时显式指定项目 | `manual` | 上传页下拉，或批量归入 |
| 2 | 图纸图签的「工程名称」 | `drawing` | CAD 原生矢量文字优先，其次视觉模型读图签 |
| 3 | 文件名清洗后暂存 | `filename` | 前端打「项目名待核对」标记，进项目可一键重命名 |
| 4 | 都拿不到 | `none` | 停在「未分组」，等人工归类 |

从图签读到的不只是名字：**工程编号、建设单位、设计单位一起写进项目档案**，
并在项目信息卡上方标出识别依据（如「`[name] …项目`；`[client] …公司`」），让人一眼看出这名字哪来的。

`「未分组」`只作为兜底桶，里面没图纸时不在项目列表占行。

## 顺手修掉的问题

- **`db.py` 不认 `EXTRACTOR_DATA_DIR`**：测试跑起来会往运营正式库里写测试项目与任务。
  已与 `store.py` 统一路径口径，测试库彻底隔离。
- **项目改名只改了一张表**：图纸归属、AI 费用账单、导出历史三处会留孤儿数据。
  现在 `projects / jobs / ai_logs / export_history` 一起改名。
- **首屏逻辑**：启动屏只在「没有任何项目且没有任何图纸」的真首次使用时出现，
  否则用户建完项目刷新又被欢迎页挡住，会以为项目没建成。
