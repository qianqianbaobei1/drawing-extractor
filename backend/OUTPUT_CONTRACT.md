# 输出契约 v3.0

## 事实与成表边界

视觉模型只输出 boxes、circuits、extra_devices、requirements、uncertainties 五组事实。顶层缺字段或多出 title/components 时，结构校验失败。标题、回路排序、元器件汇总由程序生成。同一份通过校验的原始 JSON 输入，组装结果确定；这不等于同一图纸多次模型识别必然相同。

## 定位坐标（v3.0 新增）

circuits[].bbox 与 uncertainties[].bbox 为 {x, y, w, h} 四个 0–1 小数，表示该行/该问题在整页图纸中的相对位置，仅用于前端“点表定位”和核对时放大到对应区域。

- 坐标不参与任何数量、金额或规则计算，只影响界面高亮。
- 模型无法定位时输出 null；代码不猜坐标，也不因缺少坐标而判定提取失败。
- 越界坐标裁进页面内；裁剪后宽或高小于 0.01 视为未定位。
- 前端在缺少坐标时降级为纯表格模式并明确告知，不显示位置不可信的高亮框。

uncertainties 由 v2.0 的字符串改为对象：location（位置）、detail（问题）、bbox（可空）、source（model / program）。程序内部产生的告警（组装规则、交叉核对）只有一行文本，按“位置：问题”拆分为 location/detail，仅识别全角冒号，避免拆开英文句中的 ": "。

## 存疑项来源（v3.0 新增）

uncertainties[].source 区分两类，是一份清单能不能反复导入导出的关键：

- `model`：模型在图纸上看到但拿不准的事实，只有重新识图或人工确认才会变。
- `program`：assemble / checker 根据当前数据算出来的告警，数据一变就应重算。
- 空字符串：早期版本导出的遗留数据，来源不明。

导出 Excel 时两类写成不同行（“待人工核对项”与“程序核对告警”）。早期版本把两类写在同一行，
读回时会用 checker.py / assemble.py 独有的搜辞（如“回路逐条计数”“无法安全拆分”）和重算结果比对，
把程序告警剔掉。不这样做的后果是：用户把问题改对了，告警还留在清单里。

已确认项的 `resolved` 随任务数据一起保存（PUT /api/jobs/{id}/data），导出时以“（已确认）”前缀保留。

## 参数与格式校验

使用支持图片输入的模型、图像 detail=high、temperature=0 和 JSON object 输出模式；DeepSeek 接口显式关闭 thinking，使 temperature 参数生效。当前 DeepSeek 官方 Chat Completions 文档未将 seed 列为受支持参数，因此不发送 seed，也不声称绝对复现。模型返回长度截断、无效 JSON、缺少顶层字段或 Pydantic 类型错误时，最多要求模型修复两次；修复提示明确禁止改写识别事实。仍失败则任务失败，不生成 Excel。网络与服务端错误不会伪装为格式问题重试。

相序、型号、单位和技术要求名称保留图纸原文，不用狭窄枚举或型号正则替代人工判断；不常见的相序和单位进入待核对项。extra_devices.quantity 必须是有限正数。箱号去空白并大写，型号规格不自动改写。

## 确定性组装规则

进线回路排前，普通回路保持原输入相对顺序，无编号备用回路排后。对单个规格、规格末尾显式“×N”、开头显式“N×规格”及可安全拆分的“完整型号+完整型号”组合计数。多台同型箱体的回路器件乘箱体台数。无法安全拆分的组合保留在回路明细并进入待核对项，不以一只计入汇总。非回路设备按提示词约定填写每台数量；used_in 明确指向多台同型箱体时乘台数，否则保持原数量。

回路引用箱体、数量有效性和可直接比较的断路器数量由 checker.py 交叉核对；发现差异写入 uncertainties，不自动修改原始读数。前端和 Excel 显示待核对项。

用户在界面上确认或修改待核对项后，resolved 标记随任务数据一起保存（PUT /api/jobs/{id}/data），导出时已确认项以“（已确认）”前缀出现在技术要求的“待人工核对项”一行，原始读数不被覆盖。

## 可编辑的三类事实

界面上能改的只有回路、箱体、非回路设备三类，元器件汇总本身是只读的（由这三类推导）。
保存时只要任务保留了 raw（模型原始事实），元器件汇总与程序告警就由 assemble + checker
从这三类事实重新推导，改了断路器或箱体台数不会留下对不上的旧汇总。

非回路设备（extra_devices）支持增/删/改。调用方不传该字段时沿用当前已保存的，而不是回退到 raw，
否则用户上次补录的设备会被抹掉；传空数组才是“用户删光了”。

旧任务没有 raw 时，从已导出的 xlsx 反推：无法由回路推导的元器件还原为 extra_devices（只按规格比对，
避免同一器件被回路和额外设备各算一次；箱体永远不算额外设备），已有的程序告警按上一节规则剔除。

## AI 助手问答

助手要分清两类问题，这是提示词里最容易写坏的一条：

- **事实类**（这份图纸里有什么、多少、什么型号）——只依据清单，不臆造；清单没有的就说没有。
- **方法类**（报价策略、组价口径、常见漏项、要跟谁确认什么）——**不能拒答**。可以给通行做法，
  但必须在回答里点明“这是通行做法，不是这份图纸上写的”。

不要写“只依据清单数据回答”这种一刀切的句子：实测它会让模型把“该怎么做”也当成超纲而拒答。
反过来，经验也不能伪装成清单事实，所以两类必须分开说。涉及向甲方隐瞒、虚报的做法不给建议。

助手只做判断和措辞，不直接改数据。模型输出的 patch 先过 `assistant.validate_patch`，三类目标：

- `circuit`：只接受清单里真实存在的回路编号，字段限 phase / breaker / cable / power_kw / load_name；
- `box`：字段限 name / ip_rating / install / location / size / quantity / note，设备编号不能改
  （改了回路就找不到箱体）；
- `device`：可 add / update / remove，target 用设备名称。新增时名称必填、数量必须是正数。

不合法的修改一律丢弃，并在回复里告知用户。通过校验的修改走与手动编辑完全相同的保存路径，
带 source=AI 进变更记录，可撤销。未配置模型 Key 时直接返回 503，不用关键词匹配假装回答。

patch 项里的目标键名容错为 target / circuit_no / code / name 任意一个：上下文里用的是 circuit_no，
模型很容易照着回填。

### 空响应与截断

接口回 HTTP 200 但 `content` 为空是真实会发生的（推理型模型偶发把预算全花在推理上）。
不能把它报成“没有返回合法 JSON”：那句话后面什么都不带，用户看不出发生了什么。
现在空响应会带出 finish_reason / completion_tokens / reasoning_content 字数，并自动重试一次；
`finish_reason == "length"` 是确定性的，直接报“输出被截断”而不浪费重试。max_tokens 定 4000。

“开始核对 / 确认无误 / 下一项 / 导出”是界面本地指令，由 `parse_local_command` 识别，不消耗模型调用。

## 识别链路（v3.0）

**先把线画粗。** 国内设计院出图常用 0.012pt 的极细线，200 DPI 下覆盖率只有 3%，渲染出来是一片浅灰——
人看不清，模型也难认。`render.py` 用 `TOOLS.set_graphics_min_line_width(1.5)` 把描边强制到 1.5 个设备像素，
实测线条从 0% 深色像素变成 2.5%。这是渲染侧修正，不改变图纸事实。

**每张送检图的长边都落在 2400px 附近。** 模型服务端会降采样，继续堆像素不增加可见信息：
A4 用 205 DPI、A2 用 103 DPI、A1 用 72 DPI，都是 2400px 左右。小字靠分块放大，不靠拉高整页 DPI。

按张逐次调用，不再把全部页塞进一个请求：成套电气图动辄几十页，base64 会撞上模型单次图片数上限，
max_tokens 也装不下几十页的 JSON。每张图带页码；模型看不到自己看的是哪一页，页码由代码写入
`bbox.page`。同一页的多个块之间靠“离块边缘最远优先”去重（重叠区里那一块看得最完整）；
跨页不去重——不同页上编号相同的箱体要留给 assemble 报重复。

分块门槛与目标分辨率都在 `config/pipeline.json` 的 `render` 段（出厂：长边 320mm 触发，每块目标长边 300mm，
密集系统图自动收紧到 220mm，可用 `tile_large_pages` 整体关掉）。网格由「页面实际尺寸 ÷ 目标块长边」推导，
A4 到加长图共用同一套判据；切完立刻做 `coverage_report` 覆盖自检，铺不满整页直接抛错，不允许静默漏区。
坐标在 `vision._clip_to_page` 里从块坐标折回整页归一化值。

## 数量无法拆分时的处理

型号前缀表（MCB / RCB / MCCB / ATSE / IS- / DS-）只能识别常见写法。既没有已知前缀、数量也不明确的
写法（`MCB 1P+N`、`QF1+QF2`、`DZ47LE-63/2P`）按图纸原文留一行，note 写“按原文计入，数量待人工确认”，
并同时写一条待核对告警。**不能从汇总表里剔除**——漏一行就是少算钱。同样地，非回路设备规格未标注时
用 `(规格未标注)` 占位保留，而不是丢掉。

## 任务状态持久化

任务完成后落盘为 work/<job_id>.json，包含状态、数据、摘要、变更记录和时间戳，服务重启后仍可打开。json 缺失时从已生成的 xlsx 反推（旧任务兼容），反推结果回写为 json。进行中的任务不落盘，避免写入半成品。

任务对象必须能直接序列化成接口响应；往 job 字典里放 Pydantic 对象会让轮询拿到 500，
测试里的 `json.dumps(dict(job))` 就是为了卡住这一点。

## 版本与稳定性

任务摘要和 Excel 副标题记录模型名、提示词版本、契约版本。稳定性测试比较重复调用的结构化事实与组装结果，不用 Excel 文件逐字节相等作为条件，因为副标题包含提取时间。模型服务商升级、提示词或契约修改后，仍需用真实标注图纸复核准确率。


## 证据来源与交叉验证

字段的“证据”分两类，判定必须看来源而不是只看类型，否则模型会用自己的输出给自己作证：

| 来源 | 含义 | 能否支撑 `CONFIRMED` |
|---|---|---|
| `model_vision` | 模型在渲染图上看到并报告的值 | 否，最高 `PARSED_OK` |
| `cad_native` | DWG/DXF 矢量文字（`*_cad_texts.json`） | 是 |
| `pdf_text` | PDF 内嵌文字层 | 是 |
| `ocr` | 独立 OCR 结果 | 是 |
| `human` | 人工在工作台修改并确认 | 是 |

`extractor/corroborate.py` 把模型给出的纯事实字段（箱号、安装位置、防护等级、回路编号、断路器、电缆）
拿去原生文字里做归一化匹配（去空白/连字符、统一乘号与大小写）：

- 命中 → 该字段证据来源升级为原生来源，`review_status` 置 `CONFIRMED`；
- 未命中 → 保持 `PARSED_OK`，汇总成一条 WARNING 待核对（**未命中不等于错误**，可能是文字转曲、切片边界或原生文字缺失）；
- 没有原生文字 → 返回 `available=False`，只在前端提示“缺少第二个来源”，不写进待核对、不阻断导出。

`checker` 的 `EVIDENCE_STATUS_MISMATCH` 只拦真矛盾：字段被标为已确认却拿不出任何物理来源证据。
纯事实字段若只挂 `model_vision` 证据，不在这里报警（图片型 PDF 本来就没有第二个来源）。

## 读取盘点与项目总量

DWG 转 DXF 退出码为 0 且文件非空，只说明转换步骤返回了文件。任务摘要里的 `read_report` 另记实体、布局、外参、代理对象、单位和转换日志。`coverage_rate` 保持为空。状态分三档：`supported`（支持范围内已盘点）、`degraded`（降级且原因已写明）、`insufficient`（关键条件不足）。读取不足时，已提取的箱体和器件仍可复核，项目总量不放行。

箱体 `quantity_confirmed` 为假时，`quantity` 只表示这张图上的单箱候选。汇总不把这个 1 乘成项目采购总量，`bom_release.project_total_released` 为假。台数可以写在箱名同一行，也可以在旁边单独写成「共N台」或「×N」。两处数字不一致时不放行。同一箱号出现在两个不同安装位置时，不按箱号合并成确认总量。视觉模型给出的台数默认未确认；人在清单里改过台数后，这一台才按确认数量放行。

备用回路写了断路器或接触器规格时，按已安装的一件计入，极数不另乘。只写备用、预留或未安装时，不计入采购数量。负荷名称本身不是备用时，备注里出现「备用开关」不改变这条回路。「未装饰」不是未安装。图面提到铜排、母排、柜内线、板厚、导轨或接线端子但没有可复核的装配尺寸时，进入待核，不补估算数量。块参照里的文字和属性与模型空间文字一样进入证据，身份带上这次插入的路径。

## 导出：任何时候都能直接导出

**导出是交付动作，不被任何待核对项遮挡。** 未确认的存疑项不会拦下载，而是如实写进
Excel 的待核对区（导出前检查面板也会列出它们），让人带着问题去核对，而不是拿不到文件。

门禁机制保留但默认关闭：`config/delivery.json` 的 `export_gate.block_unresolved_default`。
若某个项目确实要求“存疑未清零不许导出”，把它改成 `true`，此时
`export_gate.blocking_severities`（出厂 `ERROR`/`WARNING`）列出的级别会拦住导出，
并可用 `force=true` 单次放行。`INFO` 级提示（例如“本图没有原生文字可交叉验证”）在任何配置下都不阻断。
